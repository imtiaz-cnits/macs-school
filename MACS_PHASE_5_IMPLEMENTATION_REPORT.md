## 1. Executive Summary

Phase 5 has successfully extended the existing Annual Monthly Fee Invoice Generation Engine into a **Universal Session-Based Fee Invoice Generation System** with strict financial safety and point-of-admission isolation.

### Core Architecture Enhancements
1. **Universal Billing Period Resolver (`resolveSetupBillingPeriods`)**:
   - `fee_month = 'Monthly'`: Expands to 12 monthly billing periods (January through December).
   - Specific Month (e.g. `March`, `April`, `November`): Generates exactly 1 invoice in that specific calendar month.
   - Scheduled `Others`: Generates strictly when an explicit scheduled month is configured.
   - Unscheduled `Others` (`fee_month = NULL`): Safely skipped from automated bulk runs.
   - `Fine` and `Admission Fee`: Strictly return `[]` (excluded from scheduled cohort billing).
2. **Admission Fee — Point-of-Admission Only**:
   - Fully isolated from the annual cohort generator (`FeeGenerationService::generate()`) and annual readiness assessment (`getSessionGenerationStatus()`).
   - Generated strictly during the actual new student registration event via `StudentController::store()`, wrapped in an ACID database transaction.
   - Retries cannot create duplicate invoices (idempotency verified).
   - Promoted and continuing students never receive Admission Fee.
3. **Session Diagnostics & Readiness (`getSessionGenerationStatus`)**: Universal assessment of all active scheduled setups (currently 86 active scheduled setups in Session 2026, excluding Admission Fee and Fine).
4. **Artisan CLI `--category=` Support**: Enhanced `fees:auto-generate` command allowing administrators to target specific categories with dry-run verification.
5. **Session Management UI Updates**: Modernized labels, indicators, and modal diagnostics in `resources/views/pages/sessions/index.blade.php`.

## 3. Detailed Business Logic Implementation

### 3.1. Universal Billing Period Resolution
Implemented in `FeeGenerationService::resolveSetupBillingPeriods(FeeSetup $setup, ?int $targetYear = null): array`:
- **Recurring Monthly Setups (`fee_month = 'Monthly'`)**: Emits 12 billing periods (`January` to `December`).
- **Specific Month Setups (e.g., `Monthly Exam Fee`, `Term Exam Fee`, scheduled `Others`)**: Emits exactly 1 billing period corresponding to the named month.
- **Session Fee / Registration Fee (`fee_month = NULL`)**: Emits exactly 1 session-start period (January / Month 01).
- **Admission Fee & Fine**: Emits 0 periods (`[]`). They are never generated by the annual bulk loop.

### 3.2. Admission Fee — Strict Point-of-Admission Rule
Implemented in `FeeGenerationService::generateAdmissionFeeForNewStudent(Student $student, ?int $actorUserId = null)`:
- Invoked strictly during `StudentController::store()`.
- Locates active Admission Fee setup for the student's class, branch, and session.
- Checks if an invoice already exists for `(student_id, fee_setup_id)` to prevent duplicates.
- Resolves custom fees from `student_custom_fees`.
- Inserts `FeeInvoice` with `amount`, `net_amount`, `due_amount`, and `status = 'Unpaid'` inside the transaction.

### 3.3. Financial Safety & Concurrency Locking
- **Zero Impact on Existing Invoices**: Existing Paid, Partial, and Unpaid invoices are checked before any insertion. If an invoice exists for the slot `(student_id, fee_setup_id, month)`, it is skipped.
- **Cancelled Invoice Integrity**: Cancelled invoices are recognized and never overwritten or duplicated.
- **MySQL Advisory Lock**: Every generation request acquires `GET_LOCK('macs_school_fee_invoice_generation_lock', 10)`.
